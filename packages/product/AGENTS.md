# Product identity and release pins

- Product skills have one canonical source: `skills/<name>/SKILL.md` and its references/assets. Keep `megaladata-automation` and `package-docs` here; a new skill gets a new directory. Do not duplicate a product skill in project/home discovery directories or publish it through Dock Skills API. Node-only source paths and reserved names live in `./skills`; never import that export from the browser-facing entrypoint. Shared Host staging delivers and verifies the full skill tree for Desktop and CLI. See the [isolation plan](../../docs/superpowers/plans/2026-10-05-package-docs-isolation.md) and [implementation journal](../../docs/testing/mega-ai-agent/package-docs-implementation.md).
- A new Product skill also updates the reserved names and passes the source catalog test. Declare generated executors in `metadata.megaladata-generated`; link required references/assets from Markdown. Source validation may defer only that declared generated file; installed validation requires it. Staging compiles the executor before inventory and carries the whole catalog, without a second resource copy list or a `skills.paths` development bridge.
- Linux Desktop DEB/AppImage and CLI payload verifiers share Host `verifyProductSkills`: both canonical skills must exist, and the shared verifier checks hashes, unlisted files, containment and linked/generated resources. External reserved or obsolete names cannot replace a bundled skill or command, even after bundle failure; show the diagnostic and preserve ordinary source precedence.
- `src/index.ts` is the canonical product identity: display name `Mega AI Agent`, slug/executable/config prefix `mega-ai-agent`, environment prefix `MEGA_AI_AGENT_`, channel-specific application IDs. Keep prod/beta/dev storage isolated.
- `Product.cliExecutable` names the independent `mega-ai-agent-cli`. Node-only profile path resolution lives in the separate `./cli-profile` export; never import Node builtins into the browser-facing product entry. CLI profile roots use channel application IDs and do not relocate Desktop data.
- `Product.wordmark` is the new-chat wordmark `Mega AI`; it is not a replacement for the full application name. Desktop WordmarkV2, TUI home, session epilogue, and CLI banners use this string.
- Linux DEB installation uses `/opt/<productSlug(channel)>`, production `/opt/mega-ai-agent`. Display names must never become filesystem paths. Desktop packaging explicitly preserves the full menu name and application metadata.
- `megaladata-release.json` pins the bundled Node, Electron, Playwright/MCP and Chromium versions and hashes. `models.json` is the build-time model snapshot. Update pins together with resource verification and platform acceptance, not opportunistically during a build. CI provisions Node and Chromium from these pins ([CI runbook](../../docs/testing/mega-ai-agent/ci-release.md)).
- `megaladata-catalogs.json` pins immutable platform-specific action catalogs. Shared staging must select the matching catalog for macOS; never pass a Linux compatibility profile to native macOS or spoof the runtime platform. The managed runtime reads the installed gesture catalog from `packages/megaladata-runtime/executor/catalog` and does not fetch it from the knowledge service.
- Update/changelog feeds remain disabled until a Megaladata-owned release endpoint is configured. Never fall back to upstream OpenCode feeds.
- Run `bun test` and `bun typecheck` here when changing identity. See [desktop instructions](../desktop/AGENTS.md) and [Linux release runbook](../../docs/testing/mega-ai-agent/linux.md).
